# taiwan-legal-deid

[English](https://github.com/lawchat-oss/taiwan-legal-deid/blob/main/README.en.md)

台灣法律文件去識別化工具。在自己的電腦上找出文件裡的人名、個資、私人公司，依用途換成擬真假名或代號；要再把 AI 的回覆換回原文，就留一份對照表。針對台灣法律文件特化，一般文件也能用。

參照 ISO/IEC 20889 的去識別化技術分類設計，提供假名化（可以換回原文）與匿名化（無法還原）兩種模式。這是設計上的參照，不是認證或合規驗證。

| 輸出 | 樣子 | 對照表 | 能不能換回 | 適合的情境 |
|---|---|---|---|---|
| 擬真假名化（預設） | 陳美玲 → 姚靜慧 | 留 | 可以 | 丟給 AI 分析，再換回原文 |
| 代號假名化（`--codes`） | 陳美玲 → 甲、手機 → 〔電話1〕 | 留 | 可以（只留年的生日換不回月日） | 要讓人一眼看出哪些地方處理過，又想能換回的時候 |
| 匿名化（`--anonymize`） | 陳美玲 → 甲、手機 → 〔電話1〕、113年5月2日 → 113年5月 | 不留 | 不行 | 人工檢查後，分享給第三方或對外發表 |

- **分辨該換與該留的**：程式先列出可能的人名、個資、機構，再由模型逐一判斷「要換／保留／不是」。法官、檢察官、律師、書記官等執行職務的人名保留，當事人、證人等私人換掉；政府機關保留，私人公司換掉。
- **法律模式（預設）**：假名化時個人行程日期不動，AI 才能照原本的日期推算期間、時效；地號保留段名，號碼整案一致地換。
- **在本機 CPU 執行**：不需要 GPU；除了第一次下載模型，不會連網。對照表是你電腦上的 JSON 檔。

每種資料怎麼換：

| 資料 | 擬真假名化（預設） | 代號假名化 | 匿名化 |
|---|---|---|---|
| 人名 | 同一個人整份換成同一個假名，姓、名分開對應（陳小姐 → 郭小姐） | 甲、乙；同一個人整份一致，只寫姓、只寫名字、綽號能對到全名的也用同一個代號；同姓多人對不上的寫「〇」，不指錯人 | 同代號假名化 |
| 私人公司 | 擬真的假公司名；上市櫃公司的簡稱、「下稱」的別名跟著換 | 只把品牌換成字母（澄嶼顧問股份有限公司 → A顧問股份有限公司），「下稱」的別名跟著換（澄嶼公司 → A公司） | 同代號假名化 |
| 身分證 | 檢查碼正確的假號碼 | 〔身分證1〕 | 同代號假名化 |
| 電話、Email、網址等 | 隨機產生的假值 | 〔電話1〕這類編號 | 同代號假名化 |
| 地址 | 同縣市的真實路名 | 只留縣市 | 只留縣市 |
| 生日 | 保留年份（年齡不變） | 只留年 | 只留年 |
| 個人行程日期 | 法律模式不動；一般模式整份位移 | 法律模式不動；一般模式只留年月 | 只留年月（判決日、起訴日等照留，Python 可以調整） |

代號會避開原文已經用過的字（例如原文有「甲方」，代號就不用甲）。匿名化使用代號、不留對照表。

> 假名化留著對照表，有對照表就能換回原文：請把對照表當成個資保管，跟假名版分開存放。匿名化不留對照表、無法還原，但不保證達到法律上的匿名：事件經過等文字仍可能讓人認出是誰，輸出是否已達法律上的匿名，要由使用者依情境判斷。工具一定會有漏網，對外分享前務必人工檢查；匿名化的輸出全是代號，漏網的真名比較顯眼，對外前更要逐一檢查。

## 範例

原文（虛構）：

> 原告陳美玲（身分證 F223456781，民國71年3月8日生，住臺中市西屯區文心路三段1999號7樓，手機 0912-345-678）與被告澄嶼顧問股份有限公司（下稱澄嶼公司）間確認僱傭關係存在事件。原告自113年5月2日起任職於澄嶼公司，陳小姐主張澄嶼公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

擬真假名化（每次執行的假名不同）：

> 原告姚靜慧（身分證 F279190746，民國71年9月8日生，住臺中市太平區太平十一街四段554號7樓，手機 0976-232-860）與被告岑智顧問股份有限公司（下稱岑智公司）間確認僱傭關係存在事件。原告自113年5月2日起任職於岑智公司，姚小姐主張岑智公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

代號假名化：

> 原告甲（身分證 〔身分證1〕，民國71年生，住臺中市〔地址1〕，手機 〔電話1〕）與被告A顧問股份有限公司（下稱A公司）間確認僱傭關係存在事件。原告自113年5月2日起任職於A公司，甲小姐主張A公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

匿名化（跟代號版只差在個人行程日期只留年月，而且沒有對照表）：

> 原告甲（身分證 〔身分證1〕，民國71年生，住臺中市〔地址1〕，手機 〔電話1〕）與被告A顧問股份有限公司（下稱A公司）間確認僱傭關係存在事件。原告自113年5月起任職於A公司，甲小姐主張A公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

範例全為虛構；擬真版換出的姓名、公司名、身分證、手機、地址是隨機產生的，可能剛好跟真實的人、公司、號碼或門牌相同。

## 安裝

需要 Python 3.10 以上。

```bash
pip install taiwan-legal-deid
```

第一次使用時會從 GitHub Release 下載模型（6 層約 244 MB、3 層約 159 MB），驗過 sha256 後存在 `~/.cache/taiwan-legal-deid`。

## 使用

### 指令列

```bash
taiwan-legal-deid 起訴狀.txt                                  # → 起訴狀.txt.fake.txt（假名版）、起訴狀.txt.map.json（對照表）
taiwan-legal-deid 起訴狀.txt --codes                          # 代號版：甲、A公司、〔電話1〕，一樣留對照表
taiwan-legal-deid 證物.txt --map 案件對照表.json             # 同一案件沿用對照表：同一個人每份文件都換成同一個假名
taiwan-legal-deid --restore AI回覆.txt 起訴狀.txt.map.json    # AI 回覆換回原文
taiwan-legal-deid 起訴狀.txt 證物.txt --anonymize             # 匿名化：每份寫 <檔名>.anon.txt，不留對照表；同一批代號一致
taiwan-legal-deid 起訴狀.txt --model 3l                       # 較快的 3 層模型
taiwan-legal-deid 病歷.txt --general                          # 一般模式：個人行程日期也處理（擬真版整份位移、代號版只留年月）
```

輸入是 UTF-8 純文字；PDF、Word 請先轉成文字。

每份文件旁邊都會留一份它自己的對照表（`<檔名>.map.json`），還原那份文件的 AI 回覆時用它。同一案件共用的對照表（`--map`）偶爾會停用少數對照：前一份文件的假名剛好是後一份文件裡的真名時，那個假名就分不出是誰。同一案件請用同一種樣子（都加或都不加 `--codes`）。

匿名化輸出無法還原。`--anonymize` 一律使用代號、不留對照表（加不加 `--codes` 都一樣），不能搭配 `--map`、`--general`。

### Python

```python
from taiwan_legal_deid import Anonymizer, Detector, Obfuscator, restore

det = Detector()                                                  # 預設 6 層；Detector("3l") 較快
fake, mapping = Obfuscator(det).pseudonymize(text)                # 擬真假名化：假名版文字、對照表
original = restore(ai_reply, mapping)                             # AI 回覆換回原文
fake, mapping = Obfuscator(det, style="code").pseudonymize(text)  # 代號假名化：甲、A公司、〔電話1〕，一樣可以還原
anon = Anonymizer(det).anonymize(text)                            # 匿名化：只回傳文字，沒有對照表
```

同一案件有多份文件時，每份文件建一個新的 `Obfuscator`，把上一份回傳的對照表傳進去（跟指令列的 `--map` 相同）；不要拿同一個 `Obfuscator` 連續處理多份文件。

```python
mapping = None
for text in texts:
    fake, mapping = Obfuscator(det, mapping=mapping).pseudonymize(text)  # 還原這份文件的 AI 回覆時，用這次回傳的 mapping
```

匿名化一次處理多份：`Anonymizer(det).anonymize_many(texts)`（先掃過全部原文，避開原文已經用過的代號；同一個 `Anonymizer` 處理的文件代號一致）。`Anonymizer` 的參數：

| 參數 | 處理什麼 | 選項（第一個是預設） |
|---|---|---|
| `event_dates` | 個人行程日期 | `month` 留年月、`year` 留年、`keep` 照留 |
| `other_dates` | 判決日等其他日期 | `keep` 照留、`month` 留年月、`year` 留年 |
| `addr` | 地址 | `city` 留縣市、`district` 留到鄉鎮市區 |

0.1.x 的 `Obfuscator.anonymize()` 還能用、結果不變（做的是假名化，回傳對照表），會發出 FutureWarning 警告、提醒改用 `pseudonymize()`，1.0 移除。要不可還原的匿名化請用 `Anonymizer`。

只要偵測、不替換：`Detector().detect(text)` 回傳每個值的位置、類型與分數。

### 離線使用

先在有網路的機器執行 `taiwan-legal-deid --download`（加 `--model 3l` 下載 3 層），再把 `~/.cache/taiwan-legal-deid` 整個資料夾複製到離線機器的同一個位置，或用環境變數 `TAIWAN_LEGAL_DEID_HOME` 指到放模型的資料夾。設 `TAIWAN_LEGAL_DEID_OFFLINE=1` 時一律不連網。

### 匿名化與代號假名化

上面的數字看偵測結果（模型判斷）。匿名化看實際輸出：直接識別資料（人名、身分證、電話、Email、網址、帳號、密碼、車牌、社群帳號等）要整個換掉、輸出不能留下原值（例如密碼被當成日期換成「1986年」算沒遮好）；生日只能剩年份，日期不能留日，地址扣掉照留的縣市後要整個換掉。同一個名字別處要換時會一起換，所以執行職務的人名照留比假名化低。

| 匿名化（`Anonymizer` 預設） | 合成：6 層 | 合成：3 層 | tw-PII-bench：6 層 | tw-PII-bench：3 層 |
|---|---|---|---|---|

## 範圍與已知限制

**範圍**：針對繁體中文的台灣文件。日文（只寫片假名的人名、株式会社、日本地址、和曆日期）不在處理範圍。

**偵測一定會有漏網和誤判**（模型的限制，見上表），對外分享前務必人工檢查：

- 聊天裡只寫名字或綽號的人，常抓不到。
- 地址的頭尾較難切準（合成測試集的地址完整換掉：6 層 91%、3 層 90%）。
- 律師、法官的名字沒有職稱、單獨列在頁首或名單裡時，有時會被當成要換的人名。
- 很長的網址（超過約 220 字）有時整段抓不到。
- 事務所（律師、會計師、地政士）以及部分連鎖店、國營事業，即使是當事人或當事人任職的地方，也常被判成保留。

**設計上的取捨**（照設計運作，使用前要知道）：

- 匿名化只處理上面列的直接、間接識別資料；年齡、職業、學校、親屬關係、事件細節，以及機構名稱裡的類型、產業詞與縣市（A顧問股份有限公司的「顧問」），不會處理。
- 同姓多人時，只寫姓的稱呼（陳小姐）對不到特定的人，會寫成「〇小姐」。
- 代號只在同一個 `Anonymizer` 或同一次指令內一致；分批處理時，前後批的甲不是同一個人。逐份呼叫 `Anonymizer.anonymize()` 時，後面的文件原文如果已經用了前面編好的代號，那個人會在那份文件改用新代號並發出警告；同一批請用 `anonymize_many()` 或指令列一次處理。
- 同一案件共用對照表（`--map`）時，前一份文件的假名如果剛好是後一份文件裡的真名，那筆對照會停用、之後改用新的假名；還原各份文件的 AI 回覆時，請用那份文件自己的對照表。

代號版還原 AI 回覆時，下面這些寫法的處理：

| 寫法 | 換不換回 | 例子 |
|---|---|---|
| 單獨的代號，跟前後的字組成一般詞 | 不換回 | 甲方、甲說、甲級 |
| 單獨的機構字母 | 只在稱呼後面換回 | 被告A、（下稱A） |
| A公司，以及稱呼後面接公司類型、產業詞 | 名稱拆得出品牌時，只把字母換回品牌，後面的字照留 | A公司 → 澄嶼公司、被告A科技 → 被告澄嶼科技、被告A集團 |
| 字母跟下一個字組成一般詞 | 不換 | A棟、A咖、X光；維生素A、A/B測試也不換 |
| 只留年、年月、縣市的值 | 不換回（細節已經拿掉） | 民國71年 |
| 〔電話1〕被改寫成別的寫法 | 換不回 | — |

## 運作方式

1. **找候選（程式）**：依姓氏表（內政部）與稱謂列出可能的人名切法；身分證、電話、帳號、Email、網址、地址（內政部路名）、日期等個資；公司、商號、社區、學校等機構名稱與上市櫃簡稱。程式只負責多抓，不做判斷。
2. **判斷（模型）**：每段文字只跑一次模型，同時判斷段內每個候選「要換／保留／不是」。模型由 bert-base-chinese 微調，再從 12 層蒸餾成 6 層與 3 層，以 ONNX 在 CPU 執行。
3. **替換（程式）**：依類型換成擬真假值，或換成代號、粗化（ISO/IEC 20889 的假名化、遮蔽、粗化）；整份文件一致，同一個值在別處的寫法也一起換。

訓練資料包括公開判決（判決列名的當事人、代理人、法官、書記官等人名，先一致地換成假名）、合成法律文件與程式擴增，約 5 萬份；訓練資料不公開。

## 用自己的資料訓練

訓練程式全部公開，可以用自己標註的文件訓練。開始前要知道：

| 項目 | 說明 |
|---|---|
| 硬體 | 訓練只能在 Apple Silicon（MLX）上跑；訓練好的模型匯出成 ONNX 後，一般 CPU 就能用 |
| 起點 | 釋出的權重是推論用的 ONNX，不能接著訓練；要從 bert-base-chinese 開始訓練 |
| 資料 | 我們的訓練資料不公開，要自己準備標註好的文件（格式見下）；產生我們資料的程式也在 repo，但需要我們沒有釋出的原始檔 |
| 時間 | 我們約 5 萬份文件，在 Apple M5 Max 上每個模型（12 層、6 層、3 層）各約 30–35 分鐘 |

在 repo 根目錄執行：

```bash
python -m venv .venv && .venv/bin/pip install -e ".[train]"                  # 訓練（MLX）
python -m venv .venv-export && .venv-export/bin/pip install -e ".[export]"  # 匯出 ONNX（PyTorch）
# 把 google-bert/bert-base-chinese 下載到 base/bert-base-chinese，資料存成 data/train/synth_docs.jsonl
.venv/bin/python -m taiwan_legal_deid.train --base base/bert-base-chinese --out runs/base --epochs 3   # 先訓 12 層
.venv/bin/python -m taiwan_legal_deid.train --base base/bert-base-chinese --out runs/g6 --teacher runs/base --layers 0,1,2,3,4,5 --lr-enc 1e-4 --epochs 4   # 蒸餾成 6 層（3 層用 --layers 0,1,2）
.venv-export/bin/python -m taiwan_legal_deid.export_onnx runs/g6             # 匯出 ONNX
taiwan-legal-deid 起訴狀.txt --model runs/g6                                 # 用自己的模型；Python 是 Detector("runs/g6")
```

資料是每份文件一行 JSON（內容虛構）：

```json
{"id": "doc-001", "text": "原告陳美玲，民國71年3月8日生，手機 0912-345-678，113年5月2日到職。被告訴訟代理人王大同律師。", "spans": [{"start": 2, "end": 5, "label": "MASK", "group": "person"}, {"start": 6, "end": 15, "label": "MASK", "group": "pii"}, {"start": 20, "end": 32, "label": "MASK", "group": "pii"}, {"start": 33, "end": 41, "label": "KEEP", "group": "pii"}, {"start": 51, "end": 54, "label": "KEEP", "group": "person"}], "annot": ["person", "pii"]}
```

| 欄位 | 內容 |
|---|---|
| `id` | 文件編號，不重複；訓練程式依編號自動留 1 成當驗證資料 |
| `text` | 原文 |
| `spans` | 每個標註：`start`、`end` 是字元位置（不含 `end`）；`label` 是 `MASK`（要換）或 `KEEP`（保留）；`group` 是 `person`（人名）、`pii`（其他個資）或 `org`（機構） |
| `annot` | 這份文件完整標註了哪幾組。列出的組裡，沒有標註的候選一律當成「不是」；沒列出的組只用有標註的值 |

標註的規則：

| 資料 | 怎麼標 |
|---|---|
| 人名 | 只框名字本身（王大同，不含「律師」）；當事人、證人等私人標 `MASK`，執行職務的人標 `KEEP` |
| 日期 | 生日等身分日期標 `MASK`；個人行程日期（到職日、就醫日等）標 `KEEP`（一般模式會換、法律模式不動）；判決日等跟個人無關的日期不標 |
| 機構 | 私人公司標 `MASK`，政府機關標 `KEEP` |
| 切法 | 標註的範圍要跟程式列出的候選一樣；切法不同的候選會被當成「不是」 |

訓練完可以用 `python eval/reproduce.py --model runs/g6` 量同一組測試集。指令與參數的細節見 [`AGENTS.md`](AGENTS.md)。
