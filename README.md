# taiwan-legal-deid

[English](https://github.com/lawchat-oss/taiwan-legal-deid/blob/main/README.en.md)

台灣法律文件去識別化工具。於本機偵測文件中的人名、個人資料與私人機構，並以擬真假名或代號替換；保留對照表時，可將 AI 回覆還原為原文。以台灣法律文件為主要對象，亦可用於一般文件。

設計參照 ISO/IEC 20889 的去識別化技術分類，提供假名化（可還原）與匿名化（不可還原）兩種模式。此為設計參照，非認證或合規驗證。

| 輸出 | 範例 | 對照表 | 可還原 | 適用情境 |
|---|---|---|---|---|
| 擬真假名化（預設） | 陳美玲 → 姚靜慧 | 有 | 是 | 送交 AI 分析後還原 |
| 代號假名化（`--codes`） | 陳美玲 → 甲、手機 → 〔電話1〕 | 有 | 是（僅保留年份的生日無法還原月日） | 需標示處理位置，並保留還原能力 |
| 匿名化（`--anonymize`） | 陳美玲 → 甲、手機 → 〔電話1〕、113年5月2日 → 113年5月 | 無 | 否 | 經人工檢查後提供第三方或公開發表 |

- **區分替換與保留**：程式列出候選的人名、個人資料與機構，由模型逐一判斷「替換／保留／非目標」。執行職務者（法官、檢察官、律師、書記官等）保留，私人（當事人、證人等）替換；政府機關保留，私人公司替換。
- **法律模式（預設）**：假名化時不變更個人行程日期，保留期間與時效的推算依據；地號保留段名，號碼於整案內一致替換。
- **本機 CPU 執行**：不需 GPU；除首次下載模型外不連網。對照表為本機 JSON 檔。

> **注意**：對照表可還原原文，應視同個人資料保管，並與假名化文本分開存放。匿名化不保留對照表、不可還原，但不保證達到法律上的匿名：事件經過等內容仍可能識別特定個人，是否構成法律上的匿名須由使用者依情境判斷。偵測必有遺漏，對外提供前務必人工檢查；匿名化輸出皆為代號，遺漏的真實姓名較為明顯，對外提供前更應逐一檢查。

## 範例

原文（虛構）：

> 原告陳美玲（身分證 F223456781，民國71年3月8日生，住臺中市西屯區文心路三段1999號7樓，手機 0912-345-678）與被告澄嶼顧問股份有限公司（下稱澄嶼公司）間確認僱傭關係存在事件。原告自113年5月2日起任職於澄嶼公司，陳小姐主張澄嶼公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

擬真假名化（假名每次執行不同）：

> 原告姚靜慧（身分證 F279190746，民國71年9月8日生，住臺中市太平區太平十一街四段554號7樓，手機 0976-232-860）與被告岑智顧問股份有限公司（下稱岑智公司）間確認僱傭關係存在事件。原告自113年5月2日起任職於岑智公司，姚小姐主張岑智公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

代號假名化：

> 原告甲（身分證 〔身分證1〕，民國71年生，住臺中市〔地址1〕，手機 〔電話1〕）與被告A顧問股份有限公司（下稱A公司）間確認僱傭關係存在事件。原告自113年5月2日起任職於A公司，甲小姐主張A公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

匿名化（與代號假名化的差異：個人行程日期僅保留年月，且無對照表）：

> 原告甲（身分證 〔身分證1〕，民國71年生，住臺中市〔地址1〕，手機 〔電話1〕）與被告A顧問股份有限公司（下稱A公司）間確認僱傭關係存在事件。原告自113年5月起任職於A公司，甲小姐主張A公司違法解僱。被告訴訟代理人王大同律師。法官宋芷蘅。

範例內容均為虛構。擬真假名化產生的姓名、公司名、身分證、手機與地址為隨機產生，可能與真實的人、公司、號碼或門牌相同。

### 替換方式

| 類型 | 擬真假名化（預設） | 代號假名化 | 匿名化 |
|---|---|---|---|
| 人名 | 同一人於全文使用同一假名，姓、名分別對應（陳小姐 → 郭小姐） | 甲、乙；同一人全文一致，可對應至全名的姓、名、綽號使用同一代號 | 同代號假名化 |
| 私人公司 | 擬真假公司名；上市櫃公司簡稱與「下稱」別名同步替換 | 僅將品牌替換為字母（澄嶼顧問股份有限公司 → A顧問股份有限公司），「下稱」別名同步替換（澄嶼公司 → A公司） | 同代號假名化 |
| 身分證 | 檢查碼正確的假號碼 | 〔身分證1〕 | 同代號假名化 |
| 電話、Email、網址等 | 隨機產生的假值 | 〔電話1〕等編號 | 同代號假名化 |
| 地址 | 同縣市的真實路名 | 僅保留縣市 | 僅保留縣市 |
| 生日 | 保留年份（年齡不變） | 僅保留年份 | 僅保留年份 |
| 個人行程日期 | 法律模式不變；一般模式整份位移 | 法律模式不變；一般模式僅保留年月 | 僅保留年月（判決日、起訴日等不變，可於 Python 調整） |

代號會避開原文已使用的字（例如原文含「甲方」時不使用「甲」）。

## 安裝

需要 Python 3.10 以上。

```bash
pip install taiwan-legal-deid
```

首次使用時自 GitHub Release 下載模型（6 層約 244 MB、3 層約 159 MB），驗證 sha256 後存放於 `~/.cache/taiwan-legal-deid`。

## 使用

### 指令列

```bash
taiwan-legal-deid 起訴狀.txt                                  # 輸出 起訴狀.txt.fake.txt（假名化文本）與 起訴狀.txt.map.json（對照表）
taiwan-legal-deid 起訴狀.txt --codes                          # 代號假名化（甲、A公司、〔電話1〕），保留對照表
taiwan-legal-deid 證物.txt --map 案件對照表.json             # 沿用案件對照表：同一人於各文件使用同一假名
taiwan-legal-deid --restore AI回覆.txt 起訴狀.txt.map.json    # 將 AI 回覆還原為原文
taiwan-legal-deid 起訴狀.txt 證物.txt --anonymize             # 匿名化：各檔輸出 <檔名>.anon.txt，不留對照表；同批代號一致
taiwan-legal-deid 起訴狀.txt --model 3l                       # 使用 3 層模型（較快）
taiwan-legal-deid 病歷.txt --general                          # 一般模式：處理個人行程日期（擬真版整份位移、代號版僅保留年月）
```

輸入為 UTF-8 純文字，整份文件直接輸入即可，不需自行切分；PDF、Word 須先轉為文字。

每份文件另存其對照表（`<檔名>.map.json`），還原該文件的 AI 回覆時使用。共用案件對照表（`--map`）時，若前一份文件的假名恰為後一份文件的真實姓名，該筆對照會停用以免混淆。同一案件請使用相同輸出樣式（皆使用或皆不使用 `--codes`）。

匿名化輸出不可還原。`--anonymize` 一律使用代號、不留對照表（與是否加 `--codes` 無關），不可與 `--map`、`--general` 併用。

### Python

```python
from taiwan_legal_deid import Anonymizer, Detector, Obfuscator, restore

det = Detector()                                                  # 預設 6 層；Detector("3l") 較快
fake, mapping = Obfuscator(det).pseudonymize(text)                # 擬真假名化：回傳假名化文本與對照表
original = restore(ai_reply, mapping)                             # 將 AI 回覆還原為原文
fake, mapping = Obfuscator(det, style="code").pseudonymize(text)  # 代號假名化（甲、A公司、〔電話1〕），可還原
anon = Anonymizer(det).anonymize(text)                            # 匿名化：僅回傳文本，無對照表
```

同一案件有多份文件時，每份文件建立新的 `Obfuscator`，並傳入前一份回傳的對照表（同指令列的 `--map`）；勿以同一個 `Obfuscator` 連續處理多份文件。

```python
mapping = None
for text in texts:
    fake, mapping = Obfuscator(det, mapping=mapping).pseudonymize(text)  # 還原此文件的 AI 回覆時，使用本次回傳的 mapping
```

批次匿名化：`Anonymizer(det).anonymize_many(texts)`（先掃描全部原文以避開已使用的代號；同一個 `Anonymizer` 處理的文件代號一致）。`Anonymizer` 參數：

| 參數 | 對象 | 選項（第一項為預設） |
|---|---|---|
| `event_dates` | 個人行程日期 | `month` 保留年月、`year` 保留年、`keep` 不變 |
| `other_dates` | 判決日等其他日期 | `keep` 不變、`month` 保留年月、`year` 保留年 |
| `addr` | 地址 | `city` 保留縣市、`district` 保留至鄉鎮市區 |

0.1.x 的 `Obfuscator.anonymize()` 仍可使用且結果不變（執行假名化並回傳對照表），呼叫時發出 FutureWarning 建議改用 `pseudonymize()`，將於 1.0 移除。不可還原的匿名化請使用 `Anonymizer`。

僅偵測、不替換：`Detector().detect(text)` 回傳每個值的位置、類型與分數。

### 離線使用

於可連網的機器執行 `taiwan-legal-deid --download`（加 `--model 3l` 下載 3 層模型），再將 `~/.cache/taiwan-legal-deid` 複製到離線機器的相同位置，或以環境變數 `TAIWAN_LEGAL_DEID_HOME` 指定模型資料夾。設定 `TAIWAN_LEGAL_DEID_OFFLINE=1` 時一律不連網。

## 評測

數據以 weights-v2（套件 0.3.0）量測，可用 `python eval/reproduce.py` 重現（另需 `pip install pyarrow`）。三種輸出共用同一偵測步驟，偵測遺漏的值三種輸出皆會遺漏。

| 指標 | 定義 | 計分方式 |
|---|---|---|
| 召回率（Recall） | 應替換的值中，被替換的比例 | 標註值的每個字皆被替換才計入；部分替換視為遺漏 |
| 精確率（Precision） | 被替換的值中，確屬個人資料的比例 | 替換範圍與任一標註重疊即計入 |
| F1 | 精確率與召回率的調和平均 | — |

**本頁數字皆來自合成測試集；合成資料通常比實際文件單純，實際表現可能較低，對外分享前務必人工檢查。**

- **6 層與 3 層**：3 層於身分證、生日等少數類別略高；6 層的人名、地址較穩定，精確率亦較高，故為預設。

| 合成法律文件（`eval/data/synthetic_legal_test.jsonl`） | 75 份虛構的起訴狀、判決、筆錄、存證信函、對話紀錄、Email 等，共 21,823 字；標註 462 個應替換的人名、51 個執行職務的人名、498 個其他個人資料（含電話 74 個）。於任何評測前封存，開發期間未檢視錯誤案例（電話除外） | 一般模式 |
| [tw-PII-bench](https://huggingface.co/datasets/lianghsun/tw-PII-bench)（Liang Hsun Huang，Apache-2.0） | `crc32(id) % 2 == 1` 的 453 份（測試集；另一半為開發集） | 一般模式；不含人名，電話僅供參考 |

合成法律文件依難點分類：1 罕見姓氏、原住民與外籍人名；2 近似一般詞彙的名字；3 OCR 雜訊；4 同一值的多種寫法；5 應保留與應替換的人名並存；6 一般文件。

### 匿名化與代號假名化

上述數據評估偵測結果（模型判斷）；匿名化以實際輸出評估：直接識別資料（人名、身分證、電話、Email、網址、帳號、密碼、車牌、社群帳號等）須完整替換，且輸出不得保留原值（例如密碼被視為日期而輸出「1986年」，計為未遮蔽）；生日僅可保留年份，日期不得保留日，地址除保留的縣市外須完整替換。同一名稱於他處須替換時會一併替換，因此執行職務人名的保留率低於假名化。

| 匿名化（`Anonymizer` 預設） | 合成：6 層 | 合成：3 層 | tw-PII-bench：6 層 | tw-PII-bench：3 層 |
|---|---|---|---|---|
| 直接識別資料完整遮蔽（不含電話；tw-PII-bench 另不含人名） | 94.3% | 93.6% | 97.4% | 97.0% |
| 生日僅保留年份 | 92.7% | 95.1% | — | — |
| 地址僅保留縣市 | 86.7% | 85.6% | 94.7% | 89.8% |
| 個人行程日期僅保留年月 | 93.2% | 94.1% | — | — |
| 日期粗化（不分生日、行程） | — | — | 90.3% | 91.6% |
| 執行職務人名保留 | 96.1% | 96.1% | — | — |

代號假名化與匿名化使用相同的替換邏輯，直接識別資料、生日、地址、執行職務人名的數據與上表相同。各輸出的日期處理（合成法律文件，6 層／3 層）：

| 輸出 | 生日 | 個人行程日期 |
|---|---|---|
| 擬真假名化，法律模式（預設） | 完整替換 92.7%／95.1% | 保留 96.6%／97.5% |
| 擬真假名化，一般模式 | 完整替換 92.7%／95.1% | 完整替換 93.2%／94.1% |
| 代號假名化 | 僅保留年份 92.7%／95.1% | 保留 96.6%／97.5% |
| 匿名化 | 僅保留年份 92.7%／95.1% | 僅保留年月 93.2%／94.1% |

## 適用範圍與已知限制

**適用範圍**：台灣繁體中文文件。不處理日文（僅以片假名書寫的人名、株式会社、日本地址、和曆日期）。

**已知限制**（模型限制，見評測數據）；對外提供前務必人工檢查：

- 對話中僅以名字或綽號稱呼的人，常未偵測。
- 地址的起訖範圍不易精準切分（合成法律文件的地址完整替換：6 層 91%、3 層 90%）。
- 未附職稱、單獨出現於頁首或名單中的律師、法官姓名，可能被判定為應替換。
- 超長網址（約 220 字以上）可能整段未偵測。
- 事務所（律師、會計師、地政士）及部分連鎖店、國營事業，即使為當事人或其任職單位，也常被判定為保留。

**設計取捨**（依設計運作）：

- 匿名化僅處理上述直接與間接識別資料；年齡、職業、學校、親屬關係、事件細節，以及機構名稱中的類型、產業詞與縣市（如 A顧問股份有限公司 的「顧問」）不處理。
- 同姓多人時，僅有姓氏的稱呼（陳小姐）無法對應特定個人，輸出為「〇小姐」。
- 代號僅在同一個 `Anonymizer` 或同一次指令內一致；分批處理時，不同批次的「甲」並非同一人。逐份呼叫 `Anonymizer.anonymize()` 時，若後續文件原文已使用先前分配的代號，該人於該文件改用新代號並發出警告；同批文件請使用 `anonymize_many()` 或指令列一次處理。
- 共用案件對照表（`--map`）時，若前一份文件的假名恰為後一份文件的真實姓名，該筆對照停用，後續改用新假名；還原各文件的 AI 回覆時，請使用該文件自己的對照表。

代號假名化還原 AI 回覆時的處理規則：

| 寫法 | 是否還原 | 範例 |
|---|---|---|
| 單獨的代號與前後文字組成一般詞 | 不還原 | 甲方、甲說、甲級 |
| 單獨的機構字母 | 僅在稱謂後還原 | 被告A、（下稱A） |
| A公司，以及稱謂後接公司類型、產業詞 | 可拆出品牌時，僅將字母還原為品牌，其餘文字不變 | A公司 → 澄嶼公司、被告A科技 → 被告澄嶼科技、被告A集團 |
| 字母與下一字組成一般詞 | 不還原 | A棟、A咖、X光；維生素A、A/B測試 |
| 僅保留年、年月、縣市的值 | 不還原（細節已移除） | 民國71年 |
| 〔電話1〕被改寫為其他形式 | 無法還原 | — |

## 運作方式

1. **候選產生（程式）**：依內政部姓氏表與稱謂列出可能的人名切分；身分證、電話、帳號、Email、網址、地址（內政部路名）、日期等個人資料；公司、商號、社區、學校等機構名稱與上市櫃簡稱。此階段只求涵蓋，不做判斷。
2. **判斷（模型）**：全文自動切成約 220 字、前後重疊 60 字的視窗，每個視窗執行一次模型，同時判斷視窗內各候選「替換／保留／非目標」。模型由 bert-base-chinese 微調，並由 12 層蒸餾為 6 層與 3 層，以 ONNX 於 CPU 執行。
3. **替換（程式）**：依類型替換為擬真假值、代號或粗化值（ISO/IEC 20889 的假名化、遮蔽、粗化）；全文一致，同一值的其他寫法一併替換。

訓練資料包含公開判決（判決列名的當事人、代理人、法官、書記官等姓名先一致替換為假名）、合成法律文件與程式擴增資料，約 5 萬份；訓練資料不公開。

## 自行訓練

訓練程式碼開源，訓練資料不公開。需求與限制：

| 項目 | 說明 |
|---|---|
| 硬體 | 訓練需 Apple Silicon（MLX）；匯出為 ONNX 後可於一般 CPU 推論 |
| 起始模型 | 釋出的權重為推論用 ONNX，無法續訓；需自 bert-base-chinese 開始訓練 |
| 資料 | 需自備標註資料（格式見下）。本專案的資料產生程式包含於 repo，但其輸入未包含在內：公開判決的本機快取資料庫（SQLite），以及已標記的虛構合成文件原稿 |
| 個人資料 | 標註資料若來自真實案件即屬個人資料：僅於本機處理，勿上傳或貼至 issue，並確認具合法處理依據 |
| 訓練時間 | 約 5 萬份文件於 Apple M5 Max 上，每個模型（12、6、3 層）各約 30–35 分鐘 |

於 repo 根目錄執行：

```bash
python -m venv .venv && .venv/bin/pip install -e ".[train]"                  # 訓練環境（MLX）
python -m venv .venv-export && .venv-export/bin/pip install -e ".[export]"  # 匯出環境（PyTorch）
# 將 google-bert/bert-base-chinese 下載至 base/bert-base-chinese；若僅有 pytorch_model.bin，先執行：
#   .venv-export/bin/python -m taiwan_legal_deid.convert_base base/bert-base-chinese
# 訓練資料存為 data/train/synth_docs.jsonl（檔名固定）
.venv/bin/python -m taiwan_legal_deid.train --base base/bert-base-chinese --out runs/base --epochs 3   # 12 層（教師模型）
.venv/bin/python -m taiwan_legal_deid.train --base base/bert-base-chinese --out runs/g6 --teacher runs/base --layers 0,1,2,3,4,5 --lr-enc 1e-4 --epochs 4   # 蒸餾為 6 層（3 層：--out runs/g3 --layers 0,1,2）
.venv-export/bin/python -m taiwan_legal_deid.export_onnx runs/g6             # 匯出 ONNX
taiwan-legal-deid 起訴狀.txt --model runs/g6                                 # 使用自訓模型；Python：Detector("runs/g6")
```

資料格式為每行一份文件的 JSON（範例內容虛構）：

```json
{"id": "doc-001", "text": "原告陳美玲，民國71年3月8日生，手機 0912-345-678，113年5月2日到職。被告訴訟代理人王大同律師。", "spans": [{"start": 2, "end": 5, "label": "MASK", "group": "person"}, {"start": 6, "end": 15, "label": "MASK", "group": "pii"}, {"start": 20, "end": 32, "label": "MASK", "group": "pii"}, {"start": 33, "end": 41, "label": "KEEP", "group": "pii"}, {"start": 51, "end": 54, "label": "KEEP", "group": "person"}], "annot": ["person", "pii"]}
```

| 欄位 | 說明 |
|---|---|
| `id` | 文件編號（唯一）；依編號自動切出 10% 作為驗證集 |
| `text` | 原文 |
| `spans` | 標註清單：`start`、`end` 為字元位置（不含 `end`）；`label` 為 `MASK`（替換）或 `KEEP`（保留）；`group` 為 `person`（人名）、`pii`（其他個人資料）或 `org`（機構） |
| `annot` | 本文件完整標註的群組。列出的群組中，未標註的候選一律視為「非目標」；未列出的群組僅使用已標註的值 |

標註規則：

| 類型 | 規則 |
|---|---|
| 人名 | 僅標註姓名本身（王大同，不含「律師」）；私人（當事人、證人等）為 `MASK`，執行職務者為 `KEEP` |
| 日期 | 生日等身分日期為 `MASK`；個人行程日期（到職日、就醫日等）為 `KEEP`（一般模式替換、法律模式不變）；判決日等與個人無關的日期不標註 |
| 機構 | 私人公司為 `MASK`，政府機關為 `KEEP` |
| 範圍 | 標註範圍須與程式產生的候選一致；範圍不同的候選視為「非目標」 |

訓練後可用 `python eval/reproduce.py --model runs/g6` 以相同測試集評測。指令與參數詳見 [`AGENTS.md`](https://github.com/lawchat-oss/taiwan-legal-deid/blob/main/AGENTS.md)。
